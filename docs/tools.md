# Tool catalogue

Candidate tools for deriving SHACL shapes from an existing knowledge graph, checked against the
[inclusion criteria](../README.md#criteria-of-inclusion):

- **C1** derives (candidate) shapes from the *instance data* of an RDF KG;
- **C2** reads a local dump in a standard serialisation and/or a SPARQL endpoint;
- **C3** deterministic, not based on generative AI.

Status as of September 2026. "Tested" means the tool runs in this repository's pipeline
(`tools/<name>/`) on the toy KG; see [`results/toy/summary.md`](../results/toy/summary.md) and
[toy-findings.md](toy-findings.md).

| [SHACLGEN](https://github.com/alexiskeely/shaclgen) | any rdflib-readable file/URL (loaded in memory) | SHACL | Python, rdflib 7 | commit `a057dc3` (3.0.0b4) | ✅ file, via wrapper |
| [SHACL Play! `generate`](https://github.com/sparna-git/shacl-play) (Sparna, derived from a Cognizone algorithm) | RDF file or **SPARQL endpoint** | SHACL + VoID statistics | Java 17+, Maven build | commit `4e85078` (2026-09-21) + local patch | ✅ file + endpoint, via launcher |
| [LinkML schema-automator](https://github.com/linkml/schema-automator) `generalize-rdf` → `linkml gen-shacl` | Turtle file | LinkML schema, then SHACL | Python | schema-automator 0.5.7, linkml 1.11.1 | ✅ file (indirect route) |

Notes on execution requirements and workarounds (details in each `tools/<name>/` script):

- **sheXer** — library only (no CLI); `tools/shexer/run_shexer.py` runs it in `all_classes_mode`
  with default settings and writes both SHACL and ShExC. Endpoint mode collects the neighbourhood of
  class instances via SPARQL (`depth_for_building_subgraph`, `instances_cap` control the cost).
- **QSE** — configured through a `.properties` file generated by `tools/qse/run.sh`; needs the
  repository's `src/main/resources` queries at run time. The query-based variants
  (`qse_exact_query_based`, `qse_approximate_*`) are hard-wired to a GraphDB repository URL, so for
  now only the file-based *QSE-Exact* is wired up; *QSE-Approximate* (reservoir sampling on files)
  can be enabled by switching `qse_approximate_file` in the generated config.
- **SHACLGEN** — the PyPI release (0.2.5.2) crashes with rdflib ≥ 6 (`str.decode`) and the
  development head's console script crashes at start-up (`importlib.resources.path` on
  `shaclgen.__main__`), so `tools/shaclgen/run_shaclgen.py` calls the library directly. No endpoint
  support; loads the whole graph in memory.
- **SHACL Play!** — the `shacl-play-app` CLI cannot be built here because some dependencies are
  only published on jitpack.io (blocked by this environment's egress policy), and GitHub release
  downloads are blocked too. We build only the `shacl-generate` module and run
  `tools/shacl-play/ShaclPlayGenerate.java`, a 40-line equivalent of the CLI's `generate` command.
  At the pinned commit, `QueryExecution{Local,Remote}Service.executeSelectQuery` ignores its variable
  bindings, which makes every class get every property of the dataset;
  `tools/shacl-play/select-bindings.patch` fixes it (worth reporting upstream).
- **schema-automator** — a LinkML-first route: RDF is flattened into per-class TSV tables, a LinkML
  schema is generalised from them, and `gen-shacl` produces SHACL. Object properties become string
  slots, so it is included as a baseline for "generic schema inference" rather than a
  SHACL-native tool.

The shapes grammar (BNF) must be written by the user. Stochastic, so runs need seeds/repetitions. No Docker daemon in this sandbox. | Try driving `RDFminer-core` directly against a Corese/Fuseki endpoint through its `/core/start` API. |

| [ABSTAT](https://doi.org/10.1145/3167132.3167341)-based shape induction (Spahiu, Mihindukulasooriya et al.) | Profiles → SHACL constraints | Unclear availability of a runnable implementation | Search for code / service. |

## Excluded (with reason)

| Tool | Reason |
|---|---|
| [RDF2Graph](https://github.com/jessevdam/RDF2Graph) (2015) | Recovers the structure of a SPARQL-accessible KG, but exports only (pre-standard) ShEx, not SHACL; unmaintained since 2015. Could be revisited via a ShEx→SHACL conversion. |
| [rudof](https://github.com/rudof-project/rudof) | Validation/conversion toolkit (ShEx, SHACL, DCTAP); no data-to-shapes inference command (its `generate` goes shapes → synthetic data). Useful for ShEx↔SHACL conversion and validation. |
| [Astrea](https://link.springer.com/chapter/10.1007/978-3-030-49461-2_29), shaclgen `-o` mode | Generate shapes from *ontologies*, not instance data (fails C1). Useful as a complementary baseline when a KG ships its ontology. |
| [SCOOP](https://2024.eswc-conferences.org/wp-content/uploads/2024/05/77770191.pdf) | Integrates shapes from ontologies, RML mappings and XSD, not from the KG (fails C1). |
| [text2shacl](https://github.com/citiususc/text2shacl), [kgdc](https://github.com/ensaremirerol/kgdc), NL2SHACL-style systems | LLM-based (fail C3); candidates for the later generative-AI comparison. |
| TopBraid EDG, Stardog (`data model`) | Commercial; Stardog derives SHACL from its schema rather than from instance data. |

## Supporting software (not surveyed)

- **Apache Jena Fuseki 5.2.0** (from Maven Central) — serves a KG dump as a local SPARQL endpoint
  for tools' endpoint mode; its bundled `riot` normalises input serialisations.
- **pySHACL 0.40.1** — validates the KG against extracted shapes and the shapes against
  SHACL-SHACL in `pipeline/evaluate.py`.
